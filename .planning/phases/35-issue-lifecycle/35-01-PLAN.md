# P35-01 PLAN: Issue Lifecycle and Review State

## Objective

Separate rule-engine candidate findings from human-reviewed issue state, preparing ArchReview-KG for BCF-like workflows and repeated review cycles.

## Context

Mature review tools manage issue status and resolution history. ArchReview-KG currently writes one-shot `issues.json` rows. P35 adds lifecycle state while preserving backward compatibility.

## Tasks

1. Add lifecycle schema.
   - Candidate issue remains rule-engine output.
   - Review state layer supports `candidate`, `confirmed`, `rejected`, `needs_info`, `resolved`, `superseded`.
   - Include reviewer note, source run id, superseded-by run id, and timestamps where available.

2. Add import/export and report integration.
   - Load optional review-state file.
   - Render state in Markdown/viewer.
   - Keep old `issues.json` valid.

3. Add tests.
   - Old issue payloads validate.
   - Review state cannot turn an AI/candidate observation into a rule-engine violation.
   - Superseded/resolved state survives re-render.

## Success Criteria

- Candidate findings and confirmed defects are visibly distinct.
- Existing tests and old artifacts remain compatible.
- The schema is close enough to support BCF export later.

## Non-Goals

- Do not implement full BCFZip export in this phase.
- Do not add auth, assignees, or multi-user workflow.
