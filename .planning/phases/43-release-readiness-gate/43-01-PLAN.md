# P43-01 PLAN: Release Readiness Evidence Gate

## Objective

Add a release/demo readiness gate that turns the current evidence surface into a concrete status without using rule count as the maturity metric.

## Context

P33-P42 created the evidence-first workbench: rule-input readiness, sheet-region candidates, review state, IFC side lane, multi-sheet routing, per-sheet graph/issues preview, benchmark expansion, Studio workbench, and re-run diff. The remaining problem is release language: the project needs a machine-readable gate that says what can be claimed now and what must remain a known gap.

## Tasks

1. Build a readiness evaluator over `understanding-benchmark-suite` results.
2. Check representative run artifacts for core evidence and optional maturity evidence.
3. Expose `archkg release-readiness` with JSON and Markdown outputs.
4. Sync control artifacts and document the current expected status.

## Success Criteria

- Failed active suites, no active real drawing benchmark, or missing core run artifacts produce `not_ready`.
- Known gaps, pending rows, generated-heavy proof, or missing optional maturity artifacts prevent `evidence_ready` and produce `demo_ready_with_known_gaps`.
- The report explicitly says rule count is not a readiness metric.
- The command does not mutate review runs or benchmark specs.
- Targeted tests, ruff, mypy, benchmark suite, release-readiness smoke, and full pytest pass.
