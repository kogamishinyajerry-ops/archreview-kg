# P40-01 PLAN: Multi-Plan Benchmark Artifact Checks

## Objective

Extend the understanding benchmark suite so multi-plan artifacts are part of acceptance, not just incidental run files.

## Context

P39 added `sheet_graphs.json` and `sheet_issues.json`. Without benchmark checks, future changes could silently stop producing the correct number of per-sheet graphs or per-sheet issue previews while the older `drawing_understanding.json` checks still pass.

## Tasks

1. Extend expected specs.
   - Add optional `sheet_graphs` checks.
   - Add optional `sheet_issues` checks.
   - Support graph counts, required page indexes, per-sheet component counts, sheet counts, issue counts, and required rule IDs by page.

2. Add deterministic active case.
   - Create a committed generated multi-plan run fixture.
   - Add expected spec and provenance.
   - Add case to `samples/understanding_benchmarks/suite_manifest.json`.

3. Add regression coverage.
   - Unit-test artifact checks.
   - Packaged suite test should show active=3, pending=1, failed=0.
   - CLI suite run should pass.

## Success Criteria

- Benchmarks fail when `sheet_graphs.json` or `sheet_issues.json` no longer match expected multi-plan behavior.
- Packaged suite passes with the new active case.
- The benchmark remains recognition/artifact validation, not final compliance validation.

## Non-Goals

- Do not promote per-sheet issue previews into primary issue lifecycle.
- Do not claim real-world multi-plan recognition breadth from a deterministic generated fixture.
- Do not add a real public multi-plan expected inventory in this slice.
