# P70-01 Layout IFC Preview Validation

## Objective

Harden the 3D/IFC preview evidence loop for explicit opening/window semantics without changing rule-engine truth, default review outputs, or mandatory dependencies.

## Context

P69 provides an optional IFC preview lane from `layout_3d.json` but currently treats every doorway-like graph node as a door placeholder.

For P70, the project should recognize explicit graph-level opening evidence (`Door.properties`) as a dedicated window opening type,
export it through the optional IFC preview lane, and provide a deterministic validation path for optional real IfcOpenShell environments.

## Tasks

1. In `layout_3d.py`, classify doors as `window_opening` only when explicit evidence exists:
   - `opening_kind == "window"` or `opening_kind == "window_opening"` (case-insensitive), or
   - `is_window is True`.
2. Keep generic doors that lack explicit opening evidence as `door_opening`.
3. Map `window_opening` to `IfcWindow` in `layout_exporter._ifc_class_for_object` and ensure the preview report counts this class separately.
4. Update IFC export regression tests for mixed explicit-window fixtures:
   - fake dependency path verifies `window_opening` count in report,
   - real dependency path added with `importorskip("ifcopenshell")`.
5. Keep missing dependency behavior explicit and non-blocking for normal review flow.
6. Add/refresh `README.md`, `READINESS.md`, `CHANGELOG.md`, `.planning/ROADMAP.md`, `.planning/STATE.md`, and `70-01-SUMMARY.md` with:
   - install + optional smoke guidance,
   - `window_opening` semantic boundary,
   - unchanged rule-engine and review-state claims.

## Success Criteria

- `build_layout_3d` emits `window_opening` only on explicit evidence and keeps all counts/dims as assumptions where explicit geometry is missing.
- `layout_ifc_export` increments `IfcWindow` export counts through `window_opening` objects while preserving existing dependencies and fallback statuses.
- Fake-dependency regression tests cover both door and window opening class counts.
- Optional real-IfcOpenShell smoke test is present and guarded with `pytest.importorskip("ifcopenshell")`.
- `ruff`, `mypy archkg`, targeted tests, and full `pytest -q` pass.

## Guardrails

- Do not install or require IfcOpenShell by default.
- Do not add rule-engine semantics, review-state writes, or compliance claims to optional IFC artifacts.
- Do not perform boolean void subtraction, staircase boolean operations, or floor-stack semantics in this slice.
- Do not claim `layout.ifc` as review-grade BIM.
