# P85-01 Bundle Manager Triage Digest Plan

## Objective

Give a manager one read-only digest that consolidates the bundle's existing
dispatch and optional review queues without changing package readiness, routing,
or issue lifecycle semantics.

## Context

P67 added the primary `next_action_queue`. P78 added an opening provenance
triage queue. P82 exposed package-index optional guidance visibility. P84 added
optional guidance note closeout visibility. The bundle index now has several
useful queues, but a novice manager still has to scan multiple sections to
answer "what should I look at first?".

P85 adds a derived manager digest over those existing queues. It must not
replace the queues and must not become a new gate.

## Tasks

1. Add RED tests proving `manager_triage_digest` is derived from existing bundle
   queues and does not mutate or replace `next_action_queue`.
2. Add a top-level `manager_triage_digest` to `handoff_bundle_index.v1` with:
   - queue counts for primary next actions, opening provenance triage,
     package-index optional guidance, and optional guidance note closeout;
   - an ordered `items[]` list with package name, category, actor, title,
     reason, severity, source queue, and optional path/command fields;
   - a boundary warning stating the digest is manager navigation only.
3. Render a `Manager Triage Digest` section in bundle Markdown and HTML.
4. Preserve all existing queues, package rows, bundle status, next actors,
   readiness, manager checklist, archive checks, source runs, `issues.json`, and
   `review_state.json`.
5. Update README, READINESS, CHANGELOG, `.planning/ROADMAP.md`,
   `.planning/STATE.md`, and add `85-01-SUMMARY.md` after implementation.

## Success Criteria

- `manager_triage_digest` exists in bundle JSON with stable schema fields and
  queue counts.
- Digest `items[]` includes entries from primary next actions, opening
  provenance triage, package-index optional guidance, and optional guidance note
  closeout when those queues exist.
- Digest severity is deterministic and conservative:
  `blocker` for blocked/invalid/drift states, `needs_info` for missing or
  needs-info review states, and `guidance` for optional navigation prompts.
- Existing `next_action_queue` remains byte-for-byte semantically unchanged by
  the digest feature.
- Bundle Markdown/HTML render the digest without removing existing sections.
- Ruff, mypy, targeted handoff tests, and full pytest pass.

## Guardrails

- Do not mutate package artifacts or source-run artifacts.
- Do not add commands that create or close optional notes from the digest.
- Do not change `package_status`, `next_actor`, `next_action_queue`, manager
  checklist, archive checks, source runs, `issues.json`, or `review_state.json`.
- Do not treat optional guidance, weak opening provenance, or missing optional
  notes as compliance findings or package blockers.
- Keep this as a compact manager navigation surface only.

## Codex-5.3-Spark Contract

If delegated, `codex-5.3-spark` should own only the bounded implementation:

- touch `archkg/viewer/handoff_bundle.py`, `tests/test_handoff_bundle.py`, and
  mechanical docs/summary files;
- start with the failing digest test;
- reuse existing queue payloads instead of recomputing from source artifacts;
- keep all existing queue fields and status semantics unchanged;
- avoid new dependencies and architecture rewrites;
- run targeted tests before full validation.
