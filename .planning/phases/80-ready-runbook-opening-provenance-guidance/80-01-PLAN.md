# P80-01 Ready Runbook Opening Provenance Guidance Plan

## Objective

Surface package-local opening provenance guidance in the ready-runbook as
optional reviewer navigation without changing required next actions, manager
readiness, or source-run truth.

## Context

P79 put weak opening provenance guidance into the copied package-local reviewer
checklist. New reviewers using only `handoff_ready_runbook.md` still needed a
clear pointer to that guidance. P80 adds an optional guidance lane to the
runbook so the reviewer sees the prompt without treating it as a gate.

## Tasks

1. Add RED tests proving `write_handoff_ready_runbook` emits
   `optional_review_actions` when package checklist guidance is weak.
2. Render the optional action in `handoff_ready_runbook.md` with reason,
   artifact pointer, and preview-only boundary warning.
3. Preserve `next_actions`, required manager-intake steps, checklist item
   counts, and manager readiness semantics.
4. Update roadmap, state, readiness docs, changelog, README, and Notion mirror.

## Success Criteria

- Weak opening provenance guidance appears in ready-runbook JSON and Markdown.
- Fully ready packages keep `next_actions: []`.
- Optional guidance points to `artifacts/reviewer_task_checklist.md`.
- Manager checklist remains complete when the package is otherwise ready.
- Ruff, mypy, targeted pytest, and full pytest pass.

## Guardrails

- Do not mutate source runs.
- Do not add required runbook actions or manager gates.
- Do not change rules engine, `issues.json`, or `review_state.json`.
- Do not infer opening semantic, measurement, or host-wall provenance.
- Do not treat weak coverage as compliance failure or BIM completeness failure.
