# P34-01 PLAN: Sheet-Region Candidate Suggestions

## Objective

Generate reviewable sheet-region candidates for design area, title block, schedules, legends, and excluded text so users do not need to guess `--sheet-region` values manually.

## Context

P31 added manual `--sheet-region`. P32 research shows government/BIM workflows succeed by enforcing input quality before checking. P34 moves from manual crop to candidate suggestions without default automatic cropping.

## Tasks

1. Add candidate detector.
   - Analyze primitive text density, table-like line clusters, page edges, title-block patterns, revision/date fields, and drawing-region line density.
   - Output `sheet_region_candidates.json`.
   - Include evidence rows and excluded text summaries.

2. Wire into review and Studio.
   - Review runs write candidates even when no `--sheet-region` is supplied.
   - Studio displays candidates and lets user copy/apply region in a later run.
   - Manual `--sheet-region` remains authoritative.

3. Add benchmark checks.
   - Generated complex title-block fixture should identify a plausible design region and title-block region.
   - Candidate generation must not mutate graph input unless explicitly applied.

## Success Criteria

- Candidate artifact is deterministic.
- Manual crop behavior remains unchanged.
- Candidate display helps explain why title block/schedule noise exists.

## Non-Goals

- Do not auto-crop by default.
- Do not delete title-block text from primitives without explicit user/benchmark confirmation.
