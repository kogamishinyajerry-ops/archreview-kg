# P34-02 PLAN: Candidate Overlay Visualization

## Objective

Render sheet-region candidates as a visual overlay so reviewers can confirm
design/title/schedule/legend boxes before copying a region into a later
manual crop run.

## Context

P34-01 writes `sheet_region_candidates.json` and renders candidate tables. A
table alone is not enough for real drawing triage because users need to see
where the proposed box lands on the sheet.

## Tasks

1. Add overlay renderer.
   - Input: source PDF and `SheetRegionCandidateReport`.
   - Output: `sheet_region_candidates_overlay.png`.
   - Draw deterministic color-coded boxes by candidate kind.

2. Wire into review and Studio.
   - CLI review writes the overlay beside candidate JSON.
   - Studio full and inspect-only paths preserve the overlay.
   - Viewer panel displays the overlay when present.

3. Add focused tests.
   - Overlay PNG exists and contains visible colored marker pixels.
   - Pipeline writes the overlay.
   - Viewer HTML references the overlay.

## Success Criteria

- Candidate visualization is deterministic.
- No automatic crop behavior is introduced.
- Existing review and benchmark paths still pass.

## Non-Goals

- Do not add editable canvas interactions.
- Do not apply a candidate automatically.
