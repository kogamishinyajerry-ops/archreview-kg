# P77-01: Bundle Opening Provenance Triage Plan

## Objective

Aggregate opening provenance coverage signals at `handoff_bundle_index` scope so
managers can triage multiple packages by weak opening evidence coverage before
assigning reviewer load.

## Context

P76 writes `opening_provenance` into each package `handoff_manifest.json`.
The current bundle index already summarizes checklist, quality, signoff, manager,
and archive states but does not yet surface provenance coverage or weak-package
triage across the package set.

## Tasks

1. Add RED tests under `tests/test_handoff_bundle.py` for
   `handoff_bundle_index` JSON/Markdown/HTML coverage aggregation and weak-package
   counting from package manifests.
2. In `archkg/viewer/handoff_bundle.py`, read each package's
   `opening_provenance` once at summary creation and propagate semantic,
   measurement, host-wall, and all-three counts into `packages`.
3. Add aggregate fields to bundle summary for coverage totals and weak-package count.
4. Render new bundle-level provenance summary and per-package coverage/weak columns
   in Markdown and HTML.
5. Run required formatting/type checks and full/targeted tests.

## Success Criteria

- Bundle JSON/Markdown/HTML include opening provenance coverage across packages.
- Weak packages are flagged when `available` is false or any required provenance
  signal is zero.
- No package artifacts are mutated by index generation.
- Existing bundle behaviors remain unchanged for checklist, quality, signoff, and
  manager/intake readiness semantics.

## Guardrails

- No changes to rule-engine behavior, `issues.json`, or `review_state.json`.
- No inference of opening semantic/measurement/host data.
- No wall void subtraction or explicit BIM claims.
- Do not make IfcOpenShell required.
