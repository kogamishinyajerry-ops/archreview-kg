# P61-01 Plan: Reviewer Task Sequencing

## Objective

Give novice reviewers an ordered, concrete task queue for a review run so they know what to inspect first, what can wait, and which actions are forbidden.

## Context

P46 created first-hour onboarding. P47 created a preview-only per-sheet review queue. P60 created a manager index across handoff packages. The remaining usability gap is that a single run still exposes many evidence panels without a strict execution order for readiness blockers, primary issues, per-sheet previews, and handoff steps.

## Tasks

1. Add `reviewer_task_sequence.v1` builder and Markdown renderer.
2. Generate task sequence artifacts from review workbench, rule readiness, primary issues, review state, sheet preview queue, and quality flags.
3. Write `reviewer_task_sequence.json` / `.md` from CLI and Studio full runs, with inspect-only degradation.
4. Render the task sequence in report and Viewer.
5. Include task sequence artifacts in handoff packages.
6. Add focused builder, Viewer, raster-run, and handoff tests.
7. Update README, READINESS, CHANGELOG, ROADMAP, STATE, and Notion mirror.

## Success Criteria

- Full runs produce task sequence JSON/Markdown artifacts.
- The sequence prioritizes readiness blockers before open primary issues, and primary issues before per-sheet preview review.
- Confirmed/resolved primary issues are not reintroduced as open tasks.
- Viewer/report/handoff surfaces show the task sequence without changing issue state.
- Targeted tests, ruff, mypy, representative smoke, benchmark suite, release-readiness reference, and full pytest pass.
