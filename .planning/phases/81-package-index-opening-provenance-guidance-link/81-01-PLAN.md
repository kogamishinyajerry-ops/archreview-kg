# P81-01 Package Index Opening Provenance Guidance Link Plan

## Objective

Expose ready-runbook optional opening provenance guidance from the package-root
static index so novice reviewers can find the guidance without opening JSON
first.

## Context

P80 added `optional_review_actions` to `handoff_ready_runbook.json` and rendered
them in `handoff_ready_runbook.md`. The package-root `index.html` already
summarizes the ready-runbook status, but it did not surface optional guidance.
P81 keeps the guidance non-blocking while adding a visible navigation link in
the static entry page.

## Tasks

1. Add RED tests proving `index.html` links ready-runbook optional opening
   provenance guidance when the package has weak opening provenance coverage.
2. Render optional guidance inside the Ready-To-Review Runbook panel with links
   to `handoff_ready_runbook.md#optional-review-guidance` and the referenced
   package-local checklist artifact.
3. Preserve `next_actions`, required manager-intake steps, checklist item
   counts, manager readiness, and source-run immutability.
4. Update roadmap, state, readiness docs, changelog, README, and Notion mirror.

## Success Criteria

- Package-root `index.html` shows `Optional Review Guidance` when runbook
  optional actions exist.
- The index links to the runbook optional section and
  `artifacts/reviewer_task_checklist.md`.
- Otherwise-ready packages keep `next_actions: []`.
- Manager checklist remains complete when the package is otherwise ready.
- Ruff, mypy, targeted pytest, and full pytest pass.

## Guardrails

- Do not mutate source runs.
- Do not add required runbook actions or manager gates.
- Do not change rules engine, `issues.json`, or `review_state.json`.
- Do not infer opening semantic, measurement, or host-wall provenance.
- Do not treat weak coverage as compliance failure or BIM completeness failure.
