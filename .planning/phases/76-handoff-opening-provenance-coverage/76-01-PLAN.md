# P76-01 Handoff Opening Provenance Coverage Plan

## Objective

Surface opening provenance coverage in handoff packages so a novice reviewer can
see 3D/IFC opening evidence coverage without opening Studio.

## Context

P75 made opening provenance coverage available in `layout_ifc_export.v1`. The
handoff package already copies optional IFC artifacts, but its manifest,
summary, and static entry page did not expose the coverage counts.

## Tasks

1. Add a RED handoff package test that expects `opening_provenance` in
   `handoff_manifest.json`, `handoff_summary.md`, and package `index.html`.
2. Implement deterministic extraction from `layout_ifc_export.json` during
   `write_handoff_package`.
3. Render semantic, measurement, host-wall, and all-three counts in handoff
   Markdown and HTML as preview-only review prompts.
4. Update planning and readiness docs, then run targeted and full validation.

## Success Criteria

- Handoff packages with `layout_ifc_export.json` include opening provenance
  coverage in manifest, summary, and static index.
- Packages without IFC export artifacts still generate normally.
- Missing coverage is not a handoff quality blocker.
- Existing handoff, IFC, Viewer, ruff, mypy, and full pytest validation pass.

## Guardrails

- Do not change rules engine, `issues.json`, or `review_state.json`.
- Do not infer host walls, window semantics, or measurements.
- Do not perform wall void boolean subtraction.
- Do not describe GLB or IFC preview artifacts as review-grade BIM.
- Do not make IfcOpenShell required.
