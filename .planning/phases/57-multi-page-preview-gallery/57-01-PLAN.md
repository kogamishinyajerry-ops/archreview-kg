# P57-01 Plan: Multi-Page Preview Gallery

## Objective

Make Viewer/Studio source and annotated previews page-switchable so non-first-page primary issues can be reviewed visually without leaving the workbench.

## Context

P56 made issue focus page-aware but still routed non-first-page issues to PDF review because the static preview PNGs were page-0 only. The next usability gap for novice reviewers is direct visual localization on the correct page.

## Tasks

1. Add tests for multi-page preview rendering and page-aware focus support when preview pages exist.
2. Add a `preview_pages.json` artifact and shared renderer for source/annotated multi-page PNG sets while preserving legacy first-page filenames.
3. Wire Studio and standalone Viewer to write/load the preview manifest and pass it into issue focus.
4. Update the result template with page-switch controls and page-aware layer source selection.
5. Update docs, readiness notes, roadmap, state, and Notion mirror.

## Success Criteria

- `source_preview.png` and `annotated_preview.png` remain valid legacy first-page filenames.
- Multi-page PDFs also produce `source_preview_page_N.png` and `annotated_preview_page_N.png` for pages after page 1.
- `preview_pages.json` describes available source, annotated, and overlay preview pages.
- Non-first-page primary issues with preview pages render as directly preview-supported and focus the correct source/annotated page.
- Entity overlay remains clearly page-0 only.
- Targeted tests, ruff, mypy, representative multi-page Studio smoke, benchmark suite, release-readiness reference, and full pytest pass.
