# P42-01 PLAN: Primary Issue Re-Run Diff

## Objective

Let reviewers compare two review run directories and see which primary candidate issues are unchanged, changed, new, or resolved after a drawing/model revision.

## Context

P41 made one run reviewable through `review_workbench.json`, `review_state.json`, and issue-to-preview focus. The next workbench gap is revision tracking: users need to rerun a changed drawing and understand what moved without relying on per-run random `issue_id` values.

## Tasks

1. Build a read-only diff artifact over the two runs' primary `issues.json` files.
2. Match issues by stable rule/clause/page grouping, spatial ordering, and evidence fingerprints, not by generated `issue_id` or entity IDs.
3. Expose `archkg review-diff BEFORE_RUN AFTER_RUN -o review_diff.json` and keep per-sheet preview issues out of the lifecycle.

## Success Criteria

- Different per-run `issue_id` values still match as `unchanged` when issue evidence is stable.
- Same rule/clause/entity/page candidates with changed bbox/evidence are marked `changed`.
- Missing-after candidates become `resolved`; added-after candidates become `new`.
- The command does not mutate `issues.json`, `review_state.json`, rule output, or `sheet_issues.json`.
- Targeted tests, ruff, mypy, benchmark suite, and full pytest pass.
