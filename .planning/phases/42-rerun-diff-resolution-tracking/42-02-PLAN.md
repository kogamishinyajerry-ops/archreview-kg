# P42-02 PLAN: Viewer Review Diff Surface

## Objective

Render `review_diff.json` in Viewer/Studio so reviewers can see revision status next to primary issues without opening raw JSON.

## Context

P42-01 introduced a read-only diff artifact. The next usability step is to make that artifact visible in the workbench and issue list while preserving the boundary that diff status is not human review state and not compliance proof.

## Tasks

1. Add a viewer loader for `review_diff.json` with explicit missing-artifact degradation.
2. Render diff summary and item rows in the workbench panel.
3. Add per-issue diff status pills for current-run issues and link to the raw artifact.

## Success Criteria

- Viewer/Studio render unchanged / changed / new status beside after-run primary issue rows when `review_diff.json` exists.
- Resolved rows remain visible in the workbench diff table even though they are not in the current run's `issues.json`.
- Missing `review_diff.json` is described as "diff not run yet", not as "no change".
- No command or UI path mutates `review_state.json`, `issues.json`, or rule output.
- Targeted tests, ruff, mypy, benchmark suite, and full pytest pass.
