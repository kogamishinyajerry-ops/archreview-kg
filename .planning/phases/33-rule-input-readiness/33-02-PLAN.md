# P33-02 PLAN: Readiness Viewer and Report Surface

## Objective

Expose run-level readiness in the reviewer-facing outputs so users can distinguish "rule passed", "rule failed", "rule not applicable", and "rule could not run".

## Context

P33-01 creates the machine-readable artifact. This plan makes it visible in the Studio/viewer/report workflow.

## Tasks

1. Add readiness summary rendering.
   - Show counts by readiness status.
   - Group missing inputs by source: graph, ProjectMeta, room schedule, stair schedule, OCR/text, sheet region.
   - Keep wording clear that missing input is not pass.

2. Add viewer and Markdown report sections.
   - Studio result page loads `rule_input_readiness.json`.
   - Standalone `archkg viewer -d out` can re-render the panel from artifacts.
   - `report.md` includes a compact "规则输入就绪度" section.

3. Add UI/report tests.
   - Snapshot or substring tests for missing input wording.
   - Re-rendering old runs without readiness artifact degrades gracefully.

## Success Criteria

- Reviewer can see why each non-fired rule did not produce an issue.
- Old run directories remain viewable.
- `ruff`, `mypy`, and viewer/report tests pass.

## Non-Goals

- Do not change issue schema.
- Do not add human review states.
- Do not make the readiness panel a generic PM dashboard.
