# P33-01 PLAN: Rule-Input Readiness Artifact

## Objective

Create a per-run rule-input readiness artifact so a reviewer can see which rules were actually runnable on the current evidence and which were blocked by missing input, low-confidence evidence, manual-only status, or project applicability.

## Context

P32 research showed that mature intelligent review systems rely on explicit information requirements before compliance checking. ArchReview-KG already has static readiness tiers in `archkg/knowledge/readiness.py`, but no run artifact that explains rule readiness for a specific drawing.

## Tasks

1. Add run-level readiness data model and builder.
   - Inputs: rule cards, entity graph, ProjectMeta, skipped applicability results, OCR diagnostics, schedule application summaries.
   - Output: `rule_input_readiness.json`.
   - Required statuses: `ready`, `missing_input`, `low_confidence`, `manual_only`, `not_applicable`, `unsupported_entity`.

2. Wire artifact into CLI and Studio review runs.
   - `archkg review` writes `rule_input_readiness.json`.
   - Studio preserves it in run output.
   - Existing issue generation must not change.

3. Add focused tests.
   - All 32 packaged rule cards appear in the artifact.
   - Missing room/stair/project inputs are not marked ready.
   - Rules skipped by applicability are distinguishable from missing inputs.

## Success Criteria

- `rule_input_readiness.json` exists in review output.
- It covers every loaded rule card.
- Existing `issues.json` behavior is unchanged.
- `ruff`, `mypy`, and targeted tests pass.

## Non-Goals

- Do not add new compliance rules.
- Do not change rule-engine pass/fail logic.
- Do not make readiness statuses user-confirmed review states; that belongs to P35.
