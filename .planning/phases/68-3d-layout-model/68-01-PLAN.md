# P68-01 Evidence 3D Layout Model

## Objective

Add a deterministic, evidence-oriented 2.5D layout model that helps reviewers understand spaces, walls, doors, stairs, and dimensions from existing graph evidence without changing rule-engine output or claiming BIM accuracy.

## Context

The project needs a path toward 3D spatial understanding, but available open-source floorplan-to-3D projects are not mature enough to become the first hard runtime dependency for arbitrary architectural PDF/raster review. ArchReview-KG already has `sheet_graphs.json` and `entity_graph.json`; P68 should derive a bounded `layout_3d` evidence layer from those artifacts.

## Tasks

1. Add `layout_3d.v1` schema, deterministic builder, JSON/Markdown writers, and GLB export using `trimesh`.
2. Integrate full CLI and Studio review runs so they write `layout_3d.json`, `layout_3d_summary.md`, and `layout_3d.glb`.
3. Surface 3D status, object counts, assumptions, blocked reasons, and artifact links in Viewer/Studio, workbench summaries, control sync, and handoff packages.
4. Add regression tests for graph-backed generation, degraded cases, GLB readability, pipeline artifacts, viewer rendering, handoff copying, and control-sync snapshots.
5. Update roadmap, readiness, changelog, README, and research notes with the P68 boundary.

## Success Criteria

- `layout_3d.json` records `model_status`, `source_sheet_ids`, `scale_basis`, `objects`, `assumptions`, and `blocked_reasons`.
- Builder prefers `sheet_graphs.json` and falls back to `entity_graph.json`.
- Every default height/thickness assumption is explicit.
- GLB artifact is non-empty and loadable by `trimesh`.
- Viewer/Studio and handoff packages expose artifacts without presenting them as compliance conclusions.
- `ruff`, `mypy archkg`, targeted tests, and full pytest pass or any remaining blocker is explicitly documented.
