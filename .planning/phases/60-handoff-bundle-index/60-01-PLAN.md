# P60-01 Plan: Handoff Bundle Index

## Objective

Give a review manager a compact index across multiple handoff packages so they can see which packages are ready, which need missing information, and which are blocked before assigning them to novice reviewers.

## Context

P48-P59 made single handoff packages increasingly complete: package manifest, quality gate, reviewer signoff, manager checklist, archive manifest, verification, static package index, and multi-page preview assets. When several packages exist under one intake directory, a manager still has to open every package one by one.

## Tasks

1. Add a bundle-index builder that scans a parent directory of child handoff packages without mutating those packages.
2. Summarize each package's manifest, quality, signoff, manager checklist, archive manifest, archive verification, missing required artifacts, and first open action.
3. Render JSON, Markdown, and static HTML bundle index outputs.
4. Add a CLI command `archkg handoff-bundle-index <packages-root>` with default output paths in the parent directory.
5. Add tests for multi-package ready/blocked summaries, CLI output generation, and single-package-root rejection.
6. Update README, READINESS, CHANGELOG, ROADMAP, STATE, and Notion mirror.

## Success Criteria

- A parent directory containing handoff packages produces `handoff_bundle_index.json`, `.md`, and `.html`.
- The index groups packages into ready, needs-info, and blocked states from package-local artifacts.
- The command does not write into child package directories and rejects a single package directory as the root.
- Targeted tests, ruff, mypy, handoff smoke, benchmark suite, release-readiness reference, and full pytest pass.
