# P69-01 Layout IFC Export Skeleton Summary

Completed: 2026-04-29

## What Changed

- Added `archkg.ifc.layout_exporter` with `layout_ifc_export.v1` report schema, JSON/Markdown writers, optional IfcOpenShell dependency loading, and deterministic export control flow.
- Added `archkg ifc export-layout --layout ... --out ... --report ... --markdown ...`.
- Export maps `floor_slab` to `IfcSlab`, `wall` to `IfcWall`, `room_volume` / `corridor_volume` to `IfcSpace`, `door_opening` to `IfcDoor`, and `stair_placeholder` to `IfcStair`; `dimension_anchor` is skipped into report counts.
- Missing IfcOpenShell returns `dependency_missing`, writes reports when requested, exits non-zero, and does not create `layout.ifc`.
- Blocked `layout_3d` inputs return `blocked`, write reports when requested, exit non-zero, and do not create `layout.ifc`.
- Non-export statuses remove stale output at the requested IFC path so an old preview cannot be mistaken for the current command result.
- Viewer/Studio now show a `Layout IFC Preview` panel with clear missing/exported states and an explicit "not review-grade BIM" boundary.
- Handoff packages and control sync now include optional `layout.ifc`, `layout_ifc_export.json`, and `layout_ifc_export.md` artifacts when present.
- Updated README, READINESS, CHANGELOG, ROADMAP, and STATE with the P69 command, artifact names, optional dependency behavior, and boundary.

## Boundary

`layout.ifc` is an optional preview artifact derived only from `layout_3d.json`. It is not generated by default `archkg review`, does not read source PDFs, does not mutate `issues.json` or `review_state.json`, does not replace GLB/2D evidence, and is not review-grade BIM or a compliance input.
