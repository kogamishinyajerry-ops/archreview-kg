# P37-01 PLAN: Rule-Card Authoring and Citation Assistant

## Objective

Create a safe draft lane for rule-card authoring and code-citation support without allowing AI-generated content to become active compliance logic automatically.

## Context

P32 research supports AI as assistant, not judge. The highest-value assistant role is helping parse clauses into draft rule requirements, thresholds, ambiguity notes, and required entity inputs.

## Tasks

1. Define draft artifact format.
   - Include source clause, extracted threshold, required inputs, applicability, ambiguity notes, and proposed tests.
   - Status must be `draft` by default.

2. Add authoring helper command or script.
   - It may work from existing `standards_raw` extraction and local rule-card examples.
   - It must not write to active `rule_cards.yaml` unless a reviewed promotion command is later added.

3. Add validation tests.
   - Draft schema forbids active status by default.
   - Draft output records missing/ambiguous source evidence.
   - No existing rule-engine behavior changes.

## Success Criteria

- Rule-card candidates can be created and reviewed as artifacts.
- Active rule cards remain manually reviewed.
- Assistant output cannot produce final issues.

## Non-Goals

- Do not add online model calls in this phase.
- Do not expand jurisdiction scope beyond current GB corpus.
