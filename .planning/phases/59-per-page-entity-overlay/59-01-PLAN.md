# P59-01 Plan: Per-Page Entity Overlay Rendering

## Objective

Make entity overlay previews follow the same multi-page review path as source and annotated previews, so novice reviewers can inspect graph-backed sheets without losing overlay context after page 1.

## Context

P57 introduced multi-page `source` and `annotated` preview layers. P58 made handoff packaging copy every image referenced by `preview_pages.json`. Entity overlays still used the legacy first-page-only `entity_overlay.png` path, which made multi-sheet runs harder to inspect when a routed graph existed on a later page.

## Tasks

1. Add preview helper coverage for rendering overlay PNGs from multiple `EntityGraph` objects and writing overlay page entries into `preview_pages.json`.
2. Update Studio run generation to render overlay previews for the primary graph plus `sheet_graphs.json` graph-backed sheets.
3. Update standalone viewer serving so existing run directories can regenerate overlay page previews from `entity_graph.json` and `sheet_graphs.json`.
4. Extend viewer and handoff tests so non-first-page overlay assets are referenced and copied.
5. Update README, readiness notes, changelog, roadmap, state, and Notion mirror.

## Success Criteria

- `preview_pages.json` can contain multiple overlay layer entries, including non-first-page graph-backed sheets.
- Legacy `entity_overlay.png` remains available for the primary graph.
- Viewer/Studio page switching can reference non-first-page overlay images.
- Handoff packaging copies manifest-referenced overlay page images without new special-case code.
- Targeted tests, ruff, mypy, representative multi-page smoke, benchmark suite, release-readiness reference, and full pytest pass.
