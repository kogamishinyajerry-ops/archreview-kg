# P82-01 Bundle Optional Guidance Visibility Plan

## Objective

Show managers which handoff packages already expose package-index optional
opening provenance guidance, without routing that guidance through the normal
next-action queue.

## Context

P81 added static package-index links for ready-runbook optional guidance. A
manager looking only at `handoff_bundle_index` still could not see which
packages had that non-blocking guidance available. P82 adds bundle-level
visibility while preserving the strict separation from package readiness and
normal dispatch actions.

## Tasks

1. Add RED tests proving bundle JSON/Markdown/HTML surface package-index
   optional guidance availability.
2. Add summary counts and a separate `package_index_optional_guidance_queue`.
3. Preserve package `next_actor`, package status, normal `next_action_queue`,
   manager gates, and source-run immutability.
4. Update roadmap, state, readiness docs, changelog, README, and Notion mirror.

## Success Criteria

- Bundle summary counts packages/actions with index-level optional guidance.
- Bundle package rows include guidance availability, index path, runbook path,
  count, reason, and boundary warning.
- Bundle Markdown/HTML render a separate optional-guidance section.
- `next_action_queue` does not include optional guidance actions.
- Ruff, mypy, targeted pytest, and full pytest pass.

## Guardrails

- Do not mutate packages or source runs.
- Do not change normal next-action routing.
- Do not change manager readiness gates.
- Do not change rules engine, `issues.json`, or `review_state.json`.
- Do not treat weak coverage as compliance failure or BIM completeness failure.
