# P46-01 PLAN: Novice Reviewer Onboarding Pack

## Objective

Make each review run usable by a new plan-review engineer without requiring them to understand internal artifact names first.

## Context

P45 made the packaged release gate evidence-ready for benchmarked drawing classes, but a new reviewer still has to infer the right inspection order from many artifacts. The next delivery risk is onboarding friction, not rule count.

## Tasks

1. Add a guidance-only onboarding artifact for each full review run.
2. Add a Markdown quickstart generated from the same data.
3. Render the onboarding path in `report.md` and Viewer/Studio.
4. Keep onboarding strictly advisory: no issue mutation, no rule output changes, no compliance certification.
5. Update docs and planning state.

## Success Criteria

- Full CLI review and Studio full review write `reviewer_onboarding.json` and `reviewer_quickstart.md`.
- The onboarding payload contains first-hour steps, common commands, do-not-claim boundaries, and handoff checklist.
- `report.md` and Viewer expose the first-hour flow.
- Release-readiness/control-sync know about the onboarding artifacts.
- Targeted tests, ruff, mypy, benchmark suite, release-readiness smoke, and full pytest pass.
