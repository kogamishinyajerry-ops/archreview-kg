# P41-03 PLAN: Bounded Review-State Operations

## Objective

Add the first bounded state-changing workbench operation: update a primary issue's human review status in `review_state.json` without mutating `issues.json`, per-sheet preview issues, or rule-engine output.

## Context

P41-01 created `review_workbench.json` as a non-mutating summary. P41-02 added navigation action links. P41-03 can add local operations only if the boundary remains explicit: rule-engine findings stay candidate until a human updates the separate review-state layer.

## Tasks

1. Add a local `archkg review-state` command and helper that update one primary `issues.json` issue in `review_state.json`.
2. Reject unknown issue IDs and per-sheet preview IDs by requiring the target issue to exist in primary `issues.json`.
3. Render review-state operation templates in `review_workbench.json`, Viewer/Studio, and `report.md`.

## Success Criteria

- `issues.json` is byte-stable after review-state updates.
- `review_state.json` summary updates exactly one issue state.
- `superseded` requires an explicit replacement run id.
- Workbench operations remain scoped to primary `issues.json`; `sheet_issues.json` remains preview-only.
- Targeted tests, ruff, mypy, benchmark suite, and full pytest pass.
