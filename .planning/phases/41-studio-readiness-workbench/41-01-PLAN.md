# P41-01 PLAN: Review Workbench Summary Artifact

## Objective

Create a compact workbench entry artifact that lets a reviewer see the state of a run before diving into individual JSON files or lower-page panels.

## Context

P33-P40 added separate evidence surfaces: rule readiness, sheet candidates, review state, sheet classification/routing, sheet graphs, sheet issue preview, drawing understanding, and real benchmark known gaps. The result is evidence-rich but scattered. P41 starts by adding a non-invasive summary layer.

## Tasks

1. Add `review_workbench.json`.
   - Summarize drawing-understanding counts.
   - Summarize issue counts, readiness counts, review-state counts, and sheet evidence counts.
   - Include artifact availability rows, warnings, and next actions.
   - Do not change rule output or review state.

2. Write the artifact from CLI and Studio.
   - Full CLI review writes complete workbench summary.
   - Studio full review writes complete workbench summary.
   - Studio inspect-only writes partial workbench summary.

3. Surface it to reviewers.
   - Add report section.
   - Add Viewer/Studio "审图工作台总览" panel.
   - Add missing-artifact degradation for old runs.
   - Include artifact in control-sync snapshots.

## Success Criteria

- `review_workbench.json` is written in full review runs.
- Viewer and `report.md` show the workbench overview.
- Old runs without the artifact render a clear missing-workbench warning.
- Tests prove the artifact exists and does not replace lower-level evidence artifacts.

## Non-Goals

- Do not implement inline review-state editing in this slice.
- Do not aggregate per-sheet preview issues into primary `issues.json`.
- Do not alter any rule-engine conclusion.
