# P41-02 PLAN: Workbench Action Links

## Objective

Turn the workbench summary into a useful action surface by adding structured navigation links from the workbench to the evidence panels a reviewer needs next.

## Context

P41-01 created `review_workbench.json` and rendered a summary panel. It still required users to manually scan the page for the right evidence surface. P41-02 should add explicit links without mutating issues or review state.

## Tasks

1. Extend `review_workbench.json`.
   - Add stable `action_links`.
   - Each action should include id, label, target anchor, artifact, status, priority, and reason.
   - Link to source/overlay, component inventory, readiness blockers, sheet evidence, region candidates, candidate issues, review state, and report.

2. Render actions.
   - Viewer/Studio workbench panel should show click targets.
   - `report.md` should mirror the action table for static review.
   - Existing quick path remains available.

3. Preserve boundaries.
   - Links are navigation only.
   - No writeback to `review_state.json`.
   - No changes to rule-engine output or per-sheet issue promotion.

## Success Criteria

- Full review run includes `action_links` in `review_workbench.json`.
- Viewer contains visible workbench action targets.
- Report contains the same action table.
- Tests lock readiness and candidate-issue action targets.

## Non-Goals

- Do not implement inline confirmation/rejection.
- Do not add JavaScript state mutation.
- Do not aggregate sheet preview issues into primary issues.
