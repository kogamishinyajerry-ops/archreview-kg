# P84-01 Bundle Optional Guidance Note Closeout Plan

## Objective

Let managers see whether package-local optional guidance notes have been
recorded across a bundle without turning those notes into readiness, compliance,
or issue-lifecycle state.

## Context

P82 made bundle indexes show which packages expose optional guidance links in
their package index. P83 added package-local `handoff_optional_guidance_note`
JSON/Markdown so a reviewer can record whether optional guidance was reviewed,
needs more information, or is blocked.

The next small step is to aggregate the P83 note status at bundle level. This
must stay separate from `package_status`, `next_actor`, `next_action_queue`,
manager checklist status, `issues.json`, and `review_state.json`.

## Tasks

1. Add RED tests for bundle aggregation of `handoff_optional_guidance_note.json`.
2. Extend `archkg.viewer.handoff_bundle` package rows and summary counts with
   optional guidance note closeout status:
   - `optional_guidance_note_available`
   - `optional_guidance_note_status`
   - `optional_guidance_note_reviewer`
   - `optional_guidance_note_action_count`
   - `optional_guidance_note_path`
   - reviewed / needs_info / blocked / not_recorded / invalid counts
   - a separate closeout queue for packages with package-index optional guidance
     but no note, and for packages whose note is `needs_info`, `blocked`, or
     invalid
3. Render the closeout summary and queue in bundle Markdown/HTML.
4. Keep normal bundle status, next-action routing, manager checklist, archive
   checks, source runs, `issues.json`, and `review_state.json` unchanged.
5. Update README, READINESS, CHANGELOG, `.planning/ROADMAP.md`,
   `.planning/STATE.md`, and add `84-01-SUMMARY.md` after implementation.

## Success Criteria

- `archkg handoff-bundle-index` reads package-local
  `handoff_optional_guidance_note.json` when present.
- Bundle JSON includes status counts for optional guidance note closeout.
- Packages with package-index optional guidance but no note appear in a separate
  optional guidance note closeout queue.
- Packages with note status `needs_info` or `blocked` appear in the same
  closeout queue with their reviewer, status, note path, and boundary warning.
- Packages with note status `reviewed` increment reviewed count but do not enter
  required next actions.
- Invalid or malformed note files are visible as `invalid` without aborting
  bundle generation.
- Bundle `status`, `next_actor`, `next_action_queue`, `package_status`, manager
  checklist status, and archive status remain unchanged.
- Targeted handoff bundle/package tests pass, then full ruff, mypy, and pytest
  pass.

## Guardrails

- Do not mutate package-local note artifacts from the bundle command.
- Do not auto-create missing optional guidance notes.
- Do not treat missing optional guidance notes as package blockers.
- Do not confirm candidate issues or write `review_state.json`.
- Do not change rule-engine outputs or source-run artifacts.
- Do not call optional guidance note status a compliance finding, BIM
  completeness result, or review-grade evidence.

## Codex-5.3-Spark Execution Contract

`codex-5.3-spark` should own the bounded implementation slice:

- edit only `archkg/viewer/handoff_bundle.py`, affected tests, and phase/docs
  closeout files;
- follow TDD by writing the failing bundle test first;
- preserve existing P82 `package_index_optional_guidance_queue` behavior;
- import `OPTIONAL_GUIDANCE_NOTE_SCHEMA_VERSION` from
  `archkg.viewer.handoff_package` rather than duplicating schema strings;
- keep the closeout queue separate from `next_action_queue` and avoid adding
  command-style required actions for optional guidance notes;
- add no new architecture, no new dependency, and no source-run mutation path;
- run the targeted handoff tests before full repo validation;
- stop only if current bundle schemas make this impossible without changing
  readiness semantics.
