# P73-01 Opening Wall-Host Provenance Plan

## Objective

Add explicit opening host-wall provenance to `layout_3d.v1` without inferring geometry. The goal is to help reviewers understand when a door/window opening is explicitly linked to a wall or source segment in the graph.

## Context

- P71 records opening semantic provenance.
- P72 records explicit opening measurement provenance.
- P73 must only record host-wall provenance when graph fields explicitly provide it.

## Tasks

1. Add tests for explicit host-wall provenance.
   - Lock `Door.properties.opening_host_wall_id` / `host_wall_id`.
   - Lock `Door.properties.opening_host_wall_segment` / `host_wall_segment`.
   - Lock that no `opening_host` is written when explicit host fields are absent.

2. Implement minimal deterministic support.
   - Add `properties.opening_host` to door/window opening objects only from explicit graph fields.
   - Normalize source segment evidence without snapping or inference.

3. Surface the evidence.
   - Add Opening Host Wall Provenance counts to `layout_3d_summary.md`.
   - Add Viewer/Studio counts and samples.

## Success Criteria

- Opening host provenance is recorded only from explicit graph evidence.
- Missing host evidence stays absent, not inferred.
- No rule-engine, issue lifecycle, IFC dependency, or geometry boolean behavior changes.
