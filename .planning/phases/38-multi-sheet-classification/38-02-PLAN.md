# P38-02 PLAN: Protected Graph Routing

## Objective

Use the P38-01 sheet classification artifact to protect graph input from title sheets, schedules, legends, details, and elevations, while avoiding silent false negatives from uncertain classification.

## Context

The current graph builder only consumes one page. If a multi-sheet PDF starts with a title or schedule page, graph extraction can run on the wrong sheet. P38-01 made page classification visible but did not change graph behavior. This slice adds routing with explicit fallback reasons.

## Tasks

1. Add protected routing logic.
   - Route only when there is exactly one high-confidence plan page.
   - Require every excluded page to be high-confidence non-graph sheet type.
   - Fall back to legacy all-page input for single-page, unknown, low-confidence, classification-mismatch, no-plan, or multiple-plan runs.

2. Persist and surface routing evidence.
   - Write `sheet_routing.json`.
   - Render routing mode, selected pages, excluded pages, fallback reason, and guard rationale in Viewer/Studio/report.
   - Include the artifact in control-sync snapshots.

3. Wire CLI and Studio graph input.
   - Build classification from the full primitive set.
   - Apply protected routing before sheet-region crop and graph build.
   - Keep route decisions explicit; do not change rule-engine semantics.

4. Add regression coverage.
   - Unit-test selected-page routing and fallback guards.
   - Exercise a title-first multi-sheet PDF and verify graph page index moves to the plan page.
   - Keep old/single-page runs compatible.

## Success Criteria

- Title-first multi-sheet PDFs can graph the later plan page.
- `sheet_routing.json` explains whether routing happened or fell back.
- Unknown, low-confidence, and multiple-plan cases do not silently drop pages.
- Existing single-page sample behavior stays unchanged.

## Non-Goals

- Do not build multiple entity graphs for multiple plan pages.
- Do not classify with ML/VLM.
- Do not change rule cards or rule-engine compliance behavior.
