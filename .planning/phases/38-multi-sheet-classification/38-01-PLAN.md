# P38-01 PLAN: Advisory Multi-Sheet Classification Artifact

## Objective

Create a per-run `sheet_classification.json` artifact that classifies each PDF page before graph routing, without changing the existing graph builder behavior.

## Context

P32 research pushed the project toward evidence-first routing. Complex real drawing sets often mix floor plans, title sheets, legends, schedules, elevations, and detail sheets. The current graph path treats the extracted page set as one evidence pool, so reviewers need a visible classification layer before any automatic routing is trusted.

## Tasks

1. Add a deterministic sheet-classification builder.
   - Classify pages as `plan`, `schedule`, `title`, `legend`, `detail`, `elevation`, or `unknown`.
   - Record confidence, evidence texts, primitive counts, and advisory graph eligibility.

2. Wire the artifact into full review runs.
   - CLI and Studio write `sheet_classification.json` beside the existing artifacts.
   - Control sync includes the artifact in run snapshots.
   - Do not auto-skip pages or mutate `entity_graph.json` in this phase.

3. Render the classification for reviewers.
   - Viewer/Studio result pages show the classification table and missing-artifact warning.
   - `report.md` includes the same advisory summary.

4. Add regression coverage.
   - Unit test classification behavior.
   - Pipeline tests assert the artifact exists.
   - Viewer/report tests assert both normal rendering and legacy missing-artifact degradation.

## Success Criteria

- Full review runs produce `sheet_classification.json`.
- Reviewers can see page type, confidence, evidence, and graph eligibility in Viewer and report output.
- Old run directories remain viewable with an explicit warning.
- No graph-routing or compliance behavior changes yet.

## Non-Goals

- Do not introduce ML/VLM sheet classification.
- Do not auto-skip non-plan pages.
- Do not change rule-engine outputs based on classification.
