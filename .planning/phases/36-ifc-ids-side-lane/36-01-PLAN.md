# P36-01 PLAN: IFC/IDS Side Lane Spike

## Objective

Prototype an openBIM validation lane using IfcOpenShell/IfcTester so ArchReview-KG can reuse IDS-based checking instead of rebuilding the BIM checker ecosystem.

## Context

P32 research identified IDS as the standard way to express machine-checkable IFC information requirements. This lane should be independent from PDF graph extraction.

## Tasks

1. Add optional IFC/IDS validation command.
   - Proposed command: `archkg ifc validate --ifc model.ifc --ids spec.ids -o out/ifc`.
   - If IfcOpenShell/IfcTester is unavailable, print a clear optional-dependency message.

2. Map results to ArchReview-KG evidence.
   - Persist raw IDS report if available.
   - Map failures to issue-like rows with requirement, actual value, target entity, and source file.
   - Keep output separate from PDF `issues.json` until schema is proven.

3. Add minimal fixtures and tests.
   - Include tiny IFC/IDS fixture or generated test data if licensing permits.
   - Test dependency-missing path without requiring global installation.

## Success Criteria

- IFC lane can validate at least one deterministic fixture when dependency is available.
- PDF review pipeline remains decoupled.
- Missing optional dependency is not a test failure unless explicitly running IFC integration tests.

## Non-Goals

- Do not implement a custom IFC parser.
- Do not claim IFC validation covers PDF drawing recognition.
