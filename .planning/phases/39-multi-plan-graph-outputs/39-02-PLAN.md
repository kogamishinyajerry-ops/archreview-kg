# P39-02 PLAN: Per-Sheet Issue Preview

## Objective

Evaluate existing rules against each per-plan-sheet graph and store the result as a preview artifact, without changing primary `issues.json` or `review_state.json`.

## Context

P39-01 creates `sheet_graphs.json`, but reviewers still need to know what each plan sheet would trigger. Directly merging those issues into the main issue lifecycle would require stable multi-sheet issue IDs, grouping, and review-state semantics. This slice keeps the result separate and explicit.

## Tasks

1. Add `sheet_issues.v1`.
   - Run existing rule cards against each graph in `sheet_graphs.json`.
   - Group candidate issues by page.
   - Preserve skipped-rule counts.
   - Mark the artifact as preview-only and not linked to review state.

2. Wire full review runs.
   - CLI and Studio write `sheet_issues.json`.
   - Do not modify primary `issues.json`.
   - Do not modify `review_state.json`.

3. Surface the preview.
   - Viewer/Studio and `report.md` show per-sheet issue counts and rule IDs.
   - Missing artifact degrades with an explicit warning.
   - Control sync includes `sheet_issues.json`.

4. Add regression coverage.
   - Unit-test two plan sheets with per-sheet issue groups.
   - Pipeline-test a two-plan PDF.
   - Assert report/viewer/control-sync visibility.

## Success Criteria

- Multi-plan runs can show candidate issues per plan sheet.
- Primary issue lifecycle remains unchanged.
- Reviewers can inspect per-sheet issue previews without confusing them with confirmed findings.

## Non-Goals

- Do not merge preview issues into `issues.json`.
- Do not create review-state rows for preview issues.
- Do not create stable cross-run issue IDs in this slice.
