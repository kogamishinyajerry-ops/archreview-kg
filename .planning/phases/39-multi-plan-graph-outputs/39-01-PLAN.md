# P39-01 PLAN: Multi-Plan Sheet Graphs

## Objective

Generate an independent graph for each high-confidence plan sheet in a multi-sheet drawing set without changing the primary rule-engine path.

## Context

P38-02 protects the primary graph path from title/schedule-first PDFs, but multiple plan sheets still fall back to legacy graph input because there is no safe aggregation model. Complex architectural sets often include more than one plan sheet, so the workbench needs per-sheet graph evidence before it can evaluate or aggregate multi-plan compliance findings.

## Tasks

1. Add a `sheet_graphs.v1` artifact.
   - Build one `EntityGraph` per high-confidence plan sheet.
   - Record per-sheet component counts.
   - Record skipped pages with sheet type, confidence, and reason.

2. Wire full review runs.
   - CLI and Studio write `sheet_graphs.json`.
   - Apply manual sheet-region crop consistently before per-sheet graphing.
   - Keep primary `entity_graph.json`, `issues.json`, and rule-engine behavior unchanged.

3. Surface for review.
   - Viewer/Studio and `report.md` render per-sheet graph counts.
   - Missing artifact degrades with an explicit warning.
   - Control sync includes `sheet_graphs.json`.

4. Add regression coverage.
   - Unit-test two plan pages plus one schedule page.
   - Pipeline-test a two-plan PDF and assert two per-sheet graphs.
   - Keep single-page sample behavior stable.

## Success Criteria

- Multi-plan runs produce one graph entry per high-confidence plan sheet.
- Non-plan and low-confidence pages are skipped with reasons.
- Existing rule-engine output is not silently expanded or merged.

## Non-Goals

- Do not aggregate compliance issues across multiple sheet graphs.
- Do not change primary `entity_graph.json` semantics.
- Do not add new component detectors in this slice.
