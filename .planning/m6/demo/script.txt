SHOT_1_TITLE
ArchReview-KG. An evidence-first plan review platform. From upload to a reviewed, traceable, calibrated set of findings — running on your laptop in five minutes. Open source. Offline. Honest. Built around a single principle: every finding must trace back to its evidence.

SHOT_2_PROBLEM
Architectural code review is mostly manual. A reviewer opens a PDF, finds rooms, doors, corridors, stairs, then maps them against thirty-plus national-code rules. It is slow, it is error-prone, and there is rarely a paper trail showing why a finding was confirmed or rejected. Recognition models help, but they create a new problem — when an AI says a corridor is too narrow, how do you know it actually saw the corridor? Where is the evidence? We built ArchReview-KG to fix the paper-trail problem first, before we touch the recognition problem. Every claim is backed by an artifact you can open and inspect.

SHOT_3_RECOGNITION
This is a real public PDF from a Cambridge, Massachusetts building department filing. We run a single command, archkg review, and the pipeline extracts primitives, builds an entity graph, classifies sheets, and runs every applicable rule. Every detected issue lands as a candidate, never as a confirmed defect — that distinction is the foundation of the platform. The recognizer is rule-based, not learned, so its decisions are inspectable: every issue cites the rule card, the standard clause, and the specific entities it triggered against.

SHOT_4_LIFECYCLE
A candidate issue moves through a lifecycle. Confirmed. Rejected. Needs more information. Resolved. Superseded. The reviewer's verdict lives in a separate review_state artifact, never overwriting the recognizer's raw output. The knowledge graph stores every event with full lineage — who looked at this issue, when they looked, what they said, and which clause they cited. Two reviewers can disagree, and that disagreement is preserved. Confidence calibration learns from rejections without losing the underlying detection.

SHOT_5_QUALITY
This is the quality dashboard. Per-rule precision, per-rule recall, calibration reliability across confidence bins. The data comes from the knowledge graph, not from self-reports. An independent test agent — also in this repository, named archreview-test-judge — audits the score against the artifacts on disk. It can override any dimension it cannot verify, and it writes a brutally honest review next to every score. When the project's internal scorer says one hundred, the judge has, on multiple iterations, said seventy, then ninety-two, then ninety-five, then one hundred. The score in this video is the judge's final number, not the scorer's.

SHOT_6_PILOT
Deployment is one command. Either path A — a Python virtual environment and the archkg-pilot init script — or path B — docker compose up. Five minutes from clone to running web UI. SQLite, local, offline. No authentication, no cloud sync, no LLM calls. The pilot tier is intentionally narrow because we want evaluators to see exactly what they are running, on hardware they control. Production deployment, with PostgreSQL, multi-user authentication, and audit log export, is M7-plus scope and not promised in this video.

SHOT_7_LIMITATIONS
Honest limitations. The rule engine over-detects on door-width and corridor-width — that drives precision down on volume-dominant rules. The recall measurement is count-level, which means over-detected rules contribute a tautological recall of one point zero. Per-instance reviewer labelling closes that gap, and it is the first item on the M6 backlog. Sourcing diversity is still narrow — eighteen of nineteen active real public PDFs are from Massachusetts. Multi-state expansion is in flight. The synthetic reviewer panel that drives the calibration sub-score is twenty synthetic reviewers per issue with a documented target precision of zero point eight-eight. Real per-instance labelling will replace it. None of this is hidden in the README — it is in the methodology section, in the M5 closeout, and in every test-judge verdict, all of which are committed.
